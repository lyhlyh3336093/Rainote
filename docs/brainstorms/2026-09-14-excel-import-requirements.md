# 多维表格 Excel 导入功能需求文档

## Summary

为多维表格导入扩展 Excel（.xlsx）格式：上传后先预检（解析、列映射、关联文本匹配，不写库），把缺参项汇总成弹框（基础列输入统一值、关联列用记录选择器），用户确认后单事务完成导入。配套为六类基础列引入"列默认值"配置，作为缺参的第一优先来源（无默认值才弹框）。双链(21)/单向关联(18)列按记录名文本匹配目标系统已有记录，双链对称写入保证关联一致性。

---

## Problem Frame

现有导入仅接受 SQL/zip（见 `docs/brainstorms/2026-08-25-multitable-import-requirements.md`），而 Excel 是更通用的数据载体：本系统导出支持 Excel 格式，外部系统导出与人工整理的数据也多为 Excel。两类场景都无法导入：round-trip 缺一环（导出 Excel 后无法导回），外部数据只能手工逐条录入。

外部 Excel 的列与目标表通常不完全对齐：缺整列、单元格缺值是常态。现有 SQL 导入对缺失列静默用空串，不提供补数机会——数据完整性交给用户事后编辑。本需求引入"默认值优先、用户补参兜底"的链路，让缺失参数在导入时一次收齐合并入库。

关联列是难点：SQL 导入将关联类型列（18/20/21/23/24/25/26）全部排除，因为 ID 引用跨实例失效。Excel 导入按记录名文本匹配目标系统已有记录，可同时覆盖 round-trip 与外部数据两种来源；双链(21)的对称性（写入 A 表时同步更新 B 表配对列）由单事务保证一致。

---

## Key Decisions

- **Excel 来源兼容两种场景**：round-trip（本系统导出的 Excel）与外部 Excel（其他系统导出或手工整理）都支持。round-trip 为格式兼容的追加导入——导回=新增副本、原记录保留、非原地更新（更新模式见 Deferred）。列匹配采用宽松策略（同现有 SQL 导入），格式契约不预设。

- **"参数不足"含三种情形**：缺整列（目标表有该列但 Excel 无此列）、缺值（Excel 有该列但某些行单元格为空；关联列 18/21 的空单元格除外——空即不建立关联）、关联列文本匹配未命中。三者都走"默认值 → 无默认值则用户输入"链路。

- **"默认值"定义为新增的列默认值配置**：系统当前无列默认值概念（新建列空值起步、SQL 导入缺失列填空串）。本需求在列设置中为六类基础列（1 文本、2 数字、3 单选、4 多选、5 日期、7 复选框）新增默认值配置。该配置同时改变 UI 新增记录行为（预填默认值），范围扩大但语义完整。

- **默认值仅对导入与 UI 新增记录生效，不回填存量记录**。关联列（18/21）不支持默认值——关联未命中的兜底是弹框记录选择器，不是静态默认值。

- **导入目标为当前选定表（单表模型）**：沿用现有 SQL 导入的"先选表再上传"模型，一次导入只写一个目标表。跨 sheet 多表导入（含跨表源 ID 映射重建关联）留待后续迭代。

- **关联值按文本匹配**：用关联文本值（round-trip 导出的"列名_文本"列，逗号分隔的记录名）匹配被关联表现有记录的 name。外部 Excel 与跨实例迁移均适用（自关联列指向本表时，同批导入数据内的引用除外，见 Deferred）；源 ID 引用（"列名_ID"列）忽略。歧义（同名多记录）默认取 sort 最靠前的一条，进弹框可改选；未命中视为缺参走弹框。

- **预检汇总式两阶段交互**：上传后先预检（不写库），所有缺参项汇总为一个弹框（每列一项），用户逐列补值后一次性单事务导入，中途不再打断。避免逐列连弹框打断，也避免弹框期间事务悬置。

- **特殊列按类型分类处理**：21/18 按上述机制导入（21 对称写入，18 仅写自身）；公式(20/23)、lookup(26)、集合运算(24)不导入值，靠源列导入后的既有重算机制；语义关联(25)本轮排除（其反向锚点存于笔记正文中，Excel 无法重建）。

## Actors

- A1. **多维表格使用者**：在多维表格页选定目标表，上传 Excel，在缺参弹框中补值，触发导入。唯一人类触发者。

## Requirements

### 触发与文件

- R1. 现有导入入口接受 `.xlsx` 文件：文件选择器 accept 增加 `.xlsx`，与 `.sql`/`.zip` 并存；既有 SQL/zip 导入行为不变。
- R2. 上传后 sheet 选定规则：单 sheet 工作簿直接用该 sheet；多 sheet 时先匹配与当前目标表名（`NoteDwtable.name`）同名的 sheet（匹配键对齐导出端 sheet 名净化变换：`[]:*?/\` 替换为 `_`、31 字符截断），无同名 sheet 时识别"表名_p<序号>"分片 sheet 家族（导出端超 2000 行分片的产物）按序号升序合并为一张逻辑表，两者皆无才报错终止；其余 sheet 忽略并在预检结果中提示。
- R3. 导入目标为当前选定的多维表格（noteId）下的当前数据表（dwtableId），单表模型，沿用 SQL 导入的目标范围语义。
- R4. 行数上限沿用现有导入的 50000 行；文件大小预检沿用现有 10MB 上限。

### 列映射

- R5. 列映射按列名宽松匹配：Excel 表头列名与目标表 `NoteColumn.name` 字符串相等（区分大小写）即视为同列。
- R6. round-trip 兼容：表头为"列名_文本"的列视为该关联/派生列的文本列；"列名_ID"列与导出时每表首位的记录 id 列均忽略（源记录 id 不映射，每次导入创建新记录，同 SQL 导入语义）。R5 精确同名匹配优先——后缀约定与记录 id 列识别仅适用于未与任何目标列精确同名的表头；目标表存在名为"record_id"或与后缀约定同名的真实用户列时，预检报表头冲突错误，不静默丢弃其数据。
- R7. Excel 中有但目标表无对应列名的列 → 跳过该列的值，后端日志记录列名与跳过原因（不记录单元格值）。
- R8. 目标表中隐藏列（`isShow=1`）不参与导入（对称于导出的隐藏列不导出）。

### 列默认值配置

- R9. 六类基础列（1 文本、2 数字、3 单选、4 多选、5 日期、7 复选框）支持在列设置中配置默认值；其余类型（人员 11、电话 13、超链接 15、附件 17、地理位置 22、关联 18/21、公式 20/23、lookup 26、集合运算 24、语义关联 25、系统列 1001-1005）不支持。
- R10. 默认值仅对导入与 UI 新增记录生效，不回填存量记录。
- R11. UI 新增记录（新建行）时各列预填其配置的默认值，用户可修改。
- R12. 默认值须通过列类型的格式校验（如数字列默认值须为合法数字），不合法的配置在保存时拒绝。

### 预检与缺参弹框

- R13. 导入为两阶段：阶段一预检（解析 Excel、列映射、关联文本匹配、单元格类型校验、缺参与影响面汇总，不写库）返回预检清单；阶段二携带用户补参执行单事务导入。预检清单含：缺参项（基础列/关联列）、将按默认值填充的列（列名+默认值+影响行数）、将自动创建的新选项（列名+选项值）、对称写入跨表影响（被关联表名+将修改的记录数）、忽略 sheet/列的提示、歧义统计。单元格类型校验对数字(2)/日期(5)/复选框(7)列按 R12 同等语义执行，违规单元格按缺参走补值链路。
- R14. 缺参判定含三种情形：缺列（目标表有、Excel 无该列，该列全部行缺参）；缺值（Excel 有该列但某些单元格为空；关联列 18/21 的空单元格不算缺参，见 R22）；关联列文本匹配未命中（见 R22）。
- R15. 缺参填充优先级：该列配置了默认值 → 用默认值填充（不进弹框）；无默认值 → 进预检弹框。
- R16. 预检弹框每列一项（列名 + 缺失行数），用户逐列输入统一值应用到该列全部缺参处；允许留空（表示接受空值）。
- R17. 关联列（18/21）的缺参弹框为记录选择器：列出被关联表的记录供搜索选择，选中一条应用到该列全部未命中单元格；不选则留空（不建立关联）。
- R18. 弹框覆盖范围限定为六类基础列与关联列（18/21）；其余列（人员 11、电话 13、超链接 15、附件 17、地理位置 22、派生列、系统列）缺值不弹框，直接留空。
- R19. 预检结果无缺参项且无歧义项时跳过弹框直接进入导入；用户在弹框点取消则终止导入，无任何写入。

### 关联一致性

- R20. 关联列（18/21）的值来源为文本匹配：取该列的文本值（逗号分隔的记录名），逐个匹配被关联表现有记录的 `NoteRecord.name`。
- R21. 匹配歧义（被关联表同名记录多条）时默认取 sort 最靠前的一条；歧义列进入预检弹框的记录选择器（预选 sort 靠前的记录，允许改选）；匹配统计（歧义数、未命中数）在预检中可见。
- R22. 匹配未命中视为该单元格缺参，走 R15 链路（关联列无默认值，直接进弹框记录选择器）。关联列单元格为空不算缺参——空即不建立关联。
- R23. 双链列(21)对称写入：导入记录的双链值写入本表 item 时，同步更新被关联表配对列（`back_field_id` 指向的列）存量记录的 item（`linkRecordId`/`value` 追加），对称性语义与现有 UI 路径（`updateNoteRecord` 的 type=21 分支）一致。
- R24. 单向关联列(18)仅写本表 item 的 link 字段，无反向维护。

### 派生与特殊列

- R25. 公式(20/23)、lookup(26)、集合运算(24)列不导入值（Excel 中对应列忽略，缺失也不弹框）；其值由既有重算机制（`recomputeLookupColumnValues` + `recomputeSetOperationsForLookup`）派生，重算纳入阶段二同一事务内执行并随事务一并回滚（见 R31）。
- R26. 语义关联列(25)本轮排除，不导入值。
- R27. 系统列（1001 创建时间、1002 最后更新时间、1003 创建人、1004 修改人、1005 自动编号）忽略 Excel 值，按系统语义生成（导入时间/当前用户）。
- R28. 单选(3)列的 Excel 值（整格视为单一选项文本）与多选(4)列的单元格值（按英文逗号拆分为多个选项文本，与 item.value 逗号拼接存储一致）在目标列选项集中不存在时，自动创建新选项后写入值，导入不中断；选项文本自身含英文逗号时无法与多值分隔区分，列为已知限制。

### 数据写入

- R29. 每行数据创建一条新 `NoteRecord`：`dwtableId`=目标表 id、`sort`=当前最大 sort+1 递增、`name` 按首个 type=1 列值派生——同现有 SQL 导入的默认值规则。
- R30. 非排除列的单元格值写入 `NoteDwtableItem`：值 = Excel 值、用户补参值或默认值三者按优先级合并（Excel 有值用 Excel 值；缺参处依次用默认值、用户输入）；`NULL`/空的处理与现有导入一致（空串）。

### 事务与失败处理

- R31. 阶段二全部写入（目标表记录、单元格、关联对称写入对被关联表存量 item 的修改、新选项创建、派生列重算（R25））包在单个事务内；任一步骤失败抛 `ServiceException` 整体回滚。
- R32. 失败弹框提示原因，用户点确定后无脏数据（含被关联表的对称写入一并回滚）；成功弹框提示导入记录数，确定后刷新表格——均沿用现有导入 UX。

### 安全与限流

- R33. 导入按当前用户对目标多维表格的访问权限校验，复用既有归属校验（对称于现有导入）。
- R34. Excel 导入端点纳入既有速率限制，参数对称现有导入。
- R35. 导入处理与日志一律不记录单元格值，仅记录列名、行号、跳过/失败原因等元数据（可能含 PII）。
- R36. 阶段二对客户端回传的全部补参做服务端独立校验：记录选择器返回的记录 ID 须验证属于该列配置的被关联表且在当前用户有权访问范围内；文本/数字/日期等补值须通过对应列类型的格式校验；预检结果仅作展示用途，不作为阶段二的可信输入。
- R37. 预检与导入须校验关联列（18/21）配置的被关联表（property.table_id）与目标表同属一个 noteId 且通过既有归属校验；不满足时该列按不可导入处理并在预检结果中报错，不默认信任列配置指向的表。
- R38. Excel 解析设资源边界：解压比率与解压后总字节数上限（zip-bomb 防护）、单元格总数上限，超出即拒绝并返回失败；POI 4.1.2 已知漏洞（CVE-2025-31672，重复 zip 条目名校验缺失，影响 poi-ooxml <5.4.0）的处置归规划阶段。

## Key Flows

- F1. Excel 导入端到端流
  - **Trigger:** 用户选定目标表，点击导入，选择 `.xlsx` 文件。
  - **Actors:** A1
  - **Steps:** 前端上传文件发起预检（noteId、dwtableId、文件）；后端校验归属；解析工作簿、按 R2 选定 sheet；按 R5-R8 做列映射；按 R20-R22 做关联文本匹配；汇总预检清单返回（缺参项、默认值填充项、新选项创建项、对称写入跨表影响、忽略提示、歧义统计，见 R13）；若有缺参或歧义则前端弹框（R16/R17/R21），用户补值或取消；确认后前端携补参发起导入；后端单事务执行全部写入（R29-R31），含对称写入、新选项创建与派生列重算；成功返回记录数并刷新，失败回滚并弹框提示原因。
  - **Covered by:** R1, R2, R3, R5, R6, R7, R8, R13, R14, R15, R16, R17, R19, R20, R21, R22, R23, R28, R29, R30, R31, R32, R33

- F2. 双链对称写入流
  - **Trigger:** 导入的记录在某双链列(21)上有关联值。
  - **Actors:** A1
  - **Steps:** 文本匹配解析出被关联记录 id 列表；本表 item 写入 `linkRecordId`（逗号分隔）与文本值；对每个被关联记录，定位其在配对列（`back_field_id`）的存量 item，追加本新记录的引用与名称（不存在则创建）；全部在同一事务内。
  - **Covered by:** R20, R23, R31

## Acceptance Examples

- AE1. round-trip 完整导入
  - **Covers R1, R5, R6, R20, R29, R32.**
  - **Given:** 用户从表 T 导出 Excel（含"记录 id"列、"名称"列、双链列"关联_文本"与"关联_ID"双列），修改部分行的"名称"值后导回 T。
  - **When:** 上传该 Excel，无缺参。
  - **Then:** 跳过弹框直接导入；新增记录数 = 行数，原记录保留（追加语义：导回产生等量新副本，非原地更新）；"记录 id"与"关联_ID"列忽略；"名称"新值生效；双链按"关联_文本"匹配重建；成功弹框显示记录数，确定后刷新。

- AE2. 缺列用默认值
  - **Covers R9, R14, R15.**
  - **Given:** 目标表有"状态"列（单选，已配置默认值"进行中"）；Excel 无"状态"列。
  - **When:** 预检。
  - **Then:** "状态"列不进缺参弹框；导入后所有新记录的"状态"值为"进行中"。

- AE3. 缺值无默认值弹框补参
  - **Covers R14, R15, R16.**
  - **Given:** 目标表"备注"列（文本，无默认值）；Excel 有"备注"列，100 行中 30 行为空。
  - **When:** 预检。
  - **Then:** 弹框显示"备注"列一项（缺失 30 行）；用户输入"待补充"；导入后 30 行"备注"均为"待补充"，其余 70 行为 Excel 原值。

- AE4. 关联歧义取 sort 靠前
  - **Covers R21.**
  - **Given:** 被关联表 B 存在两条 name="张三"的记录（sort=5 与 sort=2）；Excel 关联文本值含"张三"。
  - **When:** 预检。
  - **Then:** 默认匹配 sort=2 的记录并预选于弹框（用户可改选）；预检结果显示歧义 1 处。

- AE5. 关联未命中走记录选择器
  - **Covers R17, R22.**
  - **Given:** Excel 关联文本值"王五"在目标被关联表中不存在。
  - **When:** 预检。
  - **Then:** 弹框中该关联列出现记录选择器；用户搜索选择已有记录"赵六"；导入后该单元格关联到"赵六"；若用户不选择，该单元格无关联。

- AE6. 对称写入更新存量记录
  - **Covers R23.**
  - **Given:** 表 A 双链列配对表 B 的列；表 B 有存量记录 r100；导入 A 表的新记录 x 关联文本值命中 r100。
  - **When:** 导入完成。
  - **Then:** B 表 r100 在配对列的 item 追加了 x 的引用与名称；A 表 x 的 item 写入 r100 的引用——双向一致，与 UI 手工建立关联的结果相同。

- AE7. 选项自动创建
  - **Covers R28.**
  - **Given:** 目标表"优先级"列（单选，选项集：高/中/低）；Excel 该列出现值"紧急"。
  - **When:** 导入。
  - **Then:** "紧急"自动追加为该列新选项；导入后单元格值为"紧急"；导入不中断。

- AE8. 失败整体回滚（含对称写入）
  - **Covers R31, R32.**
  - **Given:** 导入进行到第 50 行时写入失败（如列格式异常）。
  - **When:** 后端抛出异常。
  - **Then:** 目标表无任何新记录；被关联表 B 的存量 item 无任何修改（对称写入一并回滚）；新选项创建一并回滚；弹框提示失败原因。

- AE9. UI 新增记录预填默认值
  - **Covers R11.**
  - **Given:** 表 T"状态"列（单选）默认值"进行中"。
  - **When:** 用户在 UI 新建一行。
  - **Then:** "状态"列预填"进行中"，用户可改；存量记录不受影响。

- AE10. 多 sheet 同名匹配

  - **Then:** 使用 sheet"T1"；预检结果提示忽略"T2"“汇总"；若目标表名为"T3"则报错终止。

## Deferred / Open Questions

### From 2026-09-14 review

- **无缺参路径的预检提示展示载体未定** — R19 预检与缺参弹框 (P1, design-lens, confidence 75)

  预检通过且无缺参、无歧义时（R19 跳过弹框），忽略 sheet/列的提示等预检信息没有规定的展示位置：现有导入 UX 没有预检反馈可沿用，实现者要么自创提示形式、要么静默丢弃。需决定该路径是否保留免确认直达，并统一规定提示载体（导入前摘要 / 非阻断提示 / 并入结果弹框）。

- **记录选择器补值粒度：每列统一值 vs 按未命中名逐值选择** — R17 缺参弹框 (P2, adversarial, confidence 75)

  一列中存在多个不同未命中名（round-trip 的拼写变体、外部数据的新实体正是常态）时，用户只能选一条记录应用到该列全部未命中单元格：要么全部错关到同一条记录，要么全部留空丢关联，没有逐值正确的出路。统一值语义对基础列占位符成立，对实体引用不成立；粒度改为按 distinct 未命中名逐值选择才能承载真实数据。
